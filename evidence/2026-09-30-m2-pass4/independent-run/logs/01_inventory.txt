    fix: bring sign_contract under the paused flag (audit M2)
    
    BREAKING CLIENT CHANGE, deliberately taken on devnet rather than after mainnet.
    sign_contract gains registry_config as its FIRST account and rejects with
    Paused (6008) when registry_config.paused is true.
    
    WHY. sign_contract was the only one of the six instructions taking no
    RegistryConfig, so it could not honour the paused flag and sat entirely outside the
    kill-switch surface the other five respect. A paused program would have kept
    accepting contract signatures. Not exploitable today, since paused has no setter,
    but the fix only gets more expensive as callers accumulate.
    
    SHAPE. Copied verbatim from anchor_evidence_contract.rs rather than invented:
    Account (not mut), seeds = [b"config"], bump, first in the accounts struct; the
    require!(!registry_config.paused, Paused) as the first check in the handler.
    
    SIDE EFFECT, stated plainly: sign_contract now requires RegistryConfig to EXIST,
    not just to be unpaused. That is unreachable in practice. sign_contract requires a
    pre-existing ContractArtifact, and only anchor_evidence_contract and
    anchor_authorized_contract can create one; both already require RegistryConfig. So
    there is no state where a signable contract exists but the config does not.
    
    NOT A KILL SWITCH. This adds no setter. Known v1 limitation C stands: paused can
    still never be set to true in production. Only the coverage was made uniform, and
    limitation C now records that explicitly.
